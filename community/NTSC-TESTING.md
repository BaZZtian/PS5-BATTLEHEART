# Help wanted: NTSC-U compatibility

We are preparing a native PS5 homebrew port of **Sonic Adventure 2: Battle (GameCube)**,
using each player's own GameCube image.
There are no playable PS5 builds in this repository yet.

We do not currently have NTSC-U images available for local testing. If you own
one of these versions, you can run the preparation tool locally and contribute
metadata, a sanitized report, or a code PR. **Do not send or upload an ISO,
original executable, REL module, extracted asset, shader or download link.**
Private messaging is not an alternative for submitting game files to the project.

## Versions requested

| Project | NTSC-U disc ID | PAL disc ID for the release baseline |
| --- | --- | --- |
| Sonic Adventure 2: Battle (GameCube) | GSNE8P | GSNP8P |

Please include the revision byte and SHA-256 generated by the tool. Sharing a
disc ID does not prove that every revision works. Every reported revision remains
unverified until it has been tested with the corresponding game runtime.

## What you can contribute now

1. Run `prepare-ntsc.ps1` or `tools/prepare_region.py` as shown in the README on
   your own uncompressed `.iso` or `.gcm` file. Compressed RVZ/WIA/WBFS inputs and
   Xbox packages are not accepted by this tool.
2. Open the **Regional compatibility report** issue template. After reviewing it,
   paste `metadata.json`. It has no local ISO path and contains no original bytes.
   Never attach `input.json` or your `private-inputs` directory.
3. Developers may send code-only PRs implementing region/revision selection,
   runtime/module mappings, import compatibility or synthetic regression tests.
   Describe the problem without copying original instructions or data into the PR.

Region support must use explicit identity, revision and hash checks where needed.
Do not silently treat a PAL executable or translation as NTSC-compatible. Unknown
revisions must stay unverified or fail clearly if a build requires exact offsets.

## When playable local builds exist

Run a real console test on firmware **12.40**, using your own ISO. Complete the
generated `ps5-test-template.json` only after testing the exact candidate build.
Record the full build ID produced by the release checker, the date, a sanitized
evidence reference, and results for:

- Boot and sustained gameplay, with the tested route or level described.
- Audio and controller input.
- Saving, closing the game and loading the save again.
- Sonic: Chao/Battle content and multiplayer, with the modes described.

Set `status` to `passed` only if every required check actually passed. Keep failed
or untested checks as such. Re-running preparation does not overwrite your existing
test template. No tool automatically marks gameplay checks as passed.

Test reports must identify the exact package build, ISO SHA-256 and revision.
After code or package changes, both regional reports must be repeated for the new
build. Evidence is reviewed by maintainers; hashes and checkboxes alone do not
establish that a human completed a test.

## Release rules

The required release baseline is **PAL plus NTSC-U**, for each game and candidate
build. This does not imply support for every revision in those regions. Tested
revisions must be listed explicitly in the release notes. A new compatible
revision may be added by a reviewed PR and a new set of build-specific tests.

We will not publish a game release, label it supported, or bypass the regional
gate just because a disc header or synthetic CI test passes. GitHub source
contributions are welcome now; no public game binaries are being offered.
